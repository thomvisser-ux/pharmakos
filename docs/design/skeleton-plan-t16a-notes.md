### 2. The pacing owner: who calls Host::step, speed, skip, the one clock, stalls

**Recommendation.** The client paces, through FOUR admin-scoped methods on a second connection: `end_lull` = 90, `advance_push { int32 ms }` = 91, `end_recap` = 92, `report_host_clock { int32 elapsed_ms; int32 remaining_ms }` = 93. CHANGED BY THE CRITICS in six ways. (1) BLOCKER applied: no tick ever reaches the wire. advance_push takes game MILLISECONDS (1 to 60 000; outside that is INVALID_ARGUMENT, refused and not clamped) and answers `advanced_ms` only - the gateway converts with Ms::to_ticks_floor, stops at segment end, and reports what it actually ran; a request too small to run a tick answers advanced_ms 0 and is not an error. The client carries `asked - advanced_ms` as its remainder and never learns the tick length; segment end and match end are read from the `_status` footer every result already carries (phase RECAP / ENDED), so the response has ONE field. Speed is how many game ms the pacer asks for per wall ms; skip is advance_push{60 000} repeated with no frame wait until the footer leaves PUSH. The 60 000 cap's technical reason is that one thread owns the Surface, so a longer call starves every other connection's answers (the design's READ_TIMEOUT argument had the direction wrong and is dropped). (2) `last_hash` is DROPPED: it would be the first time the full state hash reached the wire, to a token held by the human seat's own process, with the seed public; the determinism tests own the serve thread in process and read TickReport::hash from the Surface, which is item 106(3)'s definition of parity anyway. (3) The clock report is phase-neutral, not Lull-only: valid in Lull, Recap and Ended (PHASE_CLOSED in a Push, where the sim's tick is the clock). `elapsed_ms` is host time spent in the current phase and is what moves the gateway's tick in every phase that consumes no sim tick (the existing lull_elapsed / lull_offset arithmetic generalised: a high-water mark folded into the offset when the phase ends), so the rate budget, audit stamps and token expiry keep moving in a recap, at match end and in an untimed Lull; `remaining_ms` stays what `_status` shows in a Lull and must be 0 elsewhere. Without this every token has 8 calls for a whole recap and for ever after match end - which is where the full-map unlock lands. (4) That input is bounded, with its reason stated: elapsed_ms must be monotone within a phase and may advance at most 60 000 ms per report, anything else INVALID_ARGUMENT, refused, audited; limit.rs gains the sentence that the limiter's clock is client-attested. (5) `ReportHostClockResponse { bool all_ready = 1 }`: 'Ready ends the Lull' had no wire path - Surface::all_ready is Rust-only and an admin token cannot read seat state; one aggregate bool discloses no seat's plan and rides a call the lobby already makes several times a second. (6) Confinement is stated honestly as a RULE CHANGE, not a tightening: 'no handler may step or seal, EXCEPT the admin-scoped control handlers in surface/control.rs, which may drive only the live match through Surface's three driving methods'. control.rs joins the exemption list with its own ban list (Runner, Host, World, host_mut, seal_plans, seal_playbook, snapshot, `.clone()`, file_voxel_edit, file_damage); a descriptor-driven test asserts every method it serves requires SCOPE_ADMIN; the PR asks for the AGENTS.md section 3 rule 2 sentence; the agent opens the PR and stops.

**Options and downsides.** (A, chosen) Client-paced admin methods in game ms. Downsides: four forever method names only a lobby calls; match pace follows the client's frame loop (its outcome does not - the chain is batch-independent and tested); a pacer that asks more often than a tick's worth wastes calls, so T16's pacer period is a Tuning PLACEHOLDER of 50 ms or more; pause falls out for free though the spec never asked for it; the limiter's clock outside a Push is whatever the local lobby says it is, bounded per call - acceptable because the admin token is the machine's own user, and said out loud. Downsides: REJECTED in part - one extra tick buys 8 more calls, and the end screen is open-ended; the phase-neutral method costs one int32 more than the Lull-only one and also closes the untimed-Lull hole. Its other half IS taken: the unlock is tested under the default Limits. (G) Reserve 94 for save_match now. Downsides: a name guessed before T17 knows whether save is manual or automatic; additive later.
