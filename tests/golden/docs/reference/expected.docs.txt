# Pharmakos reference

the Pharmakos command-line client: inspect a playbook, read the schema, play a scenario headless.

EVERY LINE BELOW IS GENERATED. The vocabulary comes from the checked-in gp.v1
descriptor set, the diagnostics from the verifier's catalogue and string table, and
the commands and exit codes from this binary's own tables. Nothing here is written
by hand, which is what makes it unable to drift from what the code does (spec §12,
"Generated docs"). Regenerate it with `gamectl docs`; the committed copy is
tests/golden/docs/reference/expected.docs.txt.

## Commands

verify <playbook.jsonc>   inspect a playbook and print its report and report_hash
schema [--part <name>]    print the JSON Schema a seat authors against, generated from gp.v1
docs                      print the generated reference: the schema's shape and every diagnostic
scenario run <file>       play a scenario headless and check its assertions on events and hashes
seat doctor               check this installation and report what is wrong

## Exit codes

0  everything asked for held
1  the command line was wrong; nothing ran
2  a file named on the command line could not be read
3  the answer is no: a playbook did not qualify, an assertion did not hold, a check failed
4  this build is inconsistent with itself; nothing the caller did caused it

## Diagnostics

57 codes. A code is language-neutral, append-only and never
reused; only an ERROR stops a playbook qualifying. `none at the skeleton` names the
task that owes the emitter, which is honesty about coverage rather than a gap.
